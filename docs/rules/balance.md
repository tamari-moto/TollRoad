# バランス

**バランスは検証済み。数値を調整しないこと。**
[CLAUDE.md](../../CLAUDE.md) から分離した規約のひとつ。

物流の定数だけは、**実行中に一時的に上書きして効き方を見られる**
（デバッグ画面 F5 ／ [logistics_tuning.gd](../../scripts/systems/logistics_tuning.gd)）。
これは「値を変えて回してみる」ための道具であって、**この規約の例外ではない。**
上書きはセーブされず、消せば必ず `logistics.gd` の const へ戻る。
上書きで良さそうな値が見つかっても、const を書き換えるには結局
20〜30回の通しプレイが要る。

実測（各20〜30回の通しプレイ、王国都市5＋カーレオン計6都市だった頃の地図で測定）:

| 戦略 | 中央値 | 到達ランク |
|---|---|---|
| 資源を安く買って高く売るだけ | 57,763 | SURVIVOR |
| 製作を加えて巡回 | 93,446 | SURVIVOR |
| **ボーナス都市⇄カーレオンを製作しながら往復** | **857,345** | **MASTER 11/20** |

意図された成長ルートは「アイアンホロウで鉱石→剣を作りレイヴンスパイアで売る」の反復。
剣1個の原価は鉱石2個+手数料90（約356）に対しレイヴンスパイアでは約1,860 と5倍。
最適ルートなら LEGENDARY（120万）も射程に入る一方、襲撃が連続すると破産もある。

## 上表が未再検証である理由

以下の変更のたびに前提が変わっており、**上表は測り直していない**。
この表を根拠に数値を調整する前に、実機で20〜30回の通しプレイを取り直すこと。

**王国都市を5→9に増やした際**（レイヴンスパイア含め計10都市）。巡回ルートの
総移動日数や周回効率が変わる。

**王道を環から不規則な連結グラフ（`GameData.ROYAL_ROAD_EDGES`）に変更した際。**
移動は経路探索により複数区間を自動でまたぐため、都市ペアごとの実質コスト・
日数・襲撃リスクが環のときと変わる。

**黒ゾーンでレイヴンスパイアと直結するゲートをアイアンホロウ・フォックスミア・
シルバーミアの3都市に絞った際。** ゲートでない都市からレイヴンスパイアへ向かう
実質コスト・日数が増える（王道でゲートまで歩く分）。このゲート選択は3都市とも
王道で中心寄りのため、黒ゾーンを2区間経由する方が王道の迂回より安くなる都市ペアは
存在しない（手計算で確認済み。王道の直径である oakhaven↔wyndham 間ですら、
王道の大迂回1250の方が黒ゾーン2区間ルート1550より安い）。レイヴンスパイアは
中継地点としてではなく、純粋な目的地として使う設計になった。

**物流を入れた際**（2026-08-14）。**在庫が自然に増えるのは生産地だけ**になり
（`PRODUCTION_OTHER_*` を 0 にした）、それ以外の都市の品物は
[logistics.gd](../../scripts/systems/logistics.gd) が産地から運ぶ。
消費地の在庫の上限は `IMPORT_CAP_DAYS`（3日ぶん）で産地（`MARKET_CAP_DAYS`＝4日ぶん）
より薄く、産地の方が潤沢で安いという関係は**強まっている**
（実測: 特産の産地176個・買値147前後に対し、消費地は19個・買値210前後）。
`scenario_m28.gd` が産地の優位を検査で押さえている。

ただし**上表への影響は測っていない**。供給が細くなったぶん、資源を
そのまま売る戦略はさらに厳しくなっているはずで、製作を挟む本筋のルートも
仕入れ量が変わる。この節の数値を根拠に何かを調整する前に、実機で
20〜30回の通しプレイを取り直すこと。

**在庫と需要を入れた際。** ただし意図された成長ルートが残っていることは
確認してある（20シードの自動プレイで純資産の中央値 621,261 = MASTER TRADER。
従来の実測 857,345 と同じ帯）。一方**資源をそのまま売るだけの戦略は需要の
上限で頭打ちになり、大きく落ちる**（中央値 5,942 = BANKRUPT）。これは製作を
挟ませる意図どおりだが、上表の「資源を安く買って高く売るだけ = 57,763 /
SURVIVOR」はもう当てはまらない。

## 積載の罠

資源2個（重量2）が装備1個（重量3）になるため正味+1の空きが要る。
積荷を満杯にすると製作できなくなる。
[workshop_panel.gd](../../scripts/ui/workshop_panel.gd) の `_blocked_reason()` が
これをツールチップで説明している。

## 価格を作る場所

**価格を作る場所は `price_table.gd` の1箇所に閉じること。**
[market_table.gd](../../scripts/systems/market_table.gd) は在庫と需要を持ち、
価格へ掛ける掛け率だけを返す。両方が価格を書き換えると、どちらが効いたのか
追えなくなる。
